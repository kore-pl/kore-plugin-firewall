# kore-plugin-firewall

Этот репозиторий реализует плагин управления брандмауэром/портами для kore (id `firewall`). Порядок определения: ufw → iptables → none (фиксированные пути). Записи идут через SSH, allowlist и dry-run; списки IP и блокировки при подборе пароля применяются через прокси root-action ядра — плагин не повышает привилегии и не трогает реальные правила брандмауэра хоста.

## Что делает проект

- **Протокол**: `kore.plugin.v1`, `lifecycle=lazy`, полномочие `system:admin`.
- **Методы**: `firewall.status` / `rules` / `allowPort` / `denyPort` / `deleteRule` / `ipList` / `ipAllow` / `ipDeny` / `ipRemove` / `recordFail` / `bruteSet`; простые глаголы принимаются.
- **Реальное определение**: `status` сообщает бэкенд, доступность, состояние, политику по умолчанию и число правил; `rules` возвращает настоящий список.
- **Фиксированный argv**: только `ufw` / `iptables` с фиксированными аргументами — без shell и доступа к конфигурации хоста.
- **Подбор пароля**: настраиваемый порог (5 неудач → блокировка на 10 мин); временные блокировки автоматически, без таймеров в плагине.
- **Fail-closed**: без root и канала root-action записи IP возвращают `E_NEED_ROOT` с подсказкой.

## Быстрый старт

```bash
make check    # gofmt → vet → test
make build    # собрать бинарник
make dist     # создать архив
```

Плагин запускается оболочкой kore по требованию; `info.json` объявляет полномочия и `requires_kore`.

## Частые вопросы

**В: Нужен аккаунт?**
Нет. Никаких аккаунтов, онлайн-проверок и скрытой телеметрии; конфигурация — открытый текст.

**В: Где плагины?**
Каждый плагин в своём репозитории `kore-plugin-<id>` и зависит только от `kore/pkg/pluginapi`.

**В: С чего начать?**
Прочитайте протокол и таблицу методов в README, затем полномочия в `info.json`.
